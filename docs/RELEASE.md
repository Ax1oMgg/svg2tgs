# Выпуск версии

Установщики собирает GitHub Actions (`.github/workflows/release.yml`)
по метке `vX.Y.Z`. На своём компьютере ничего собирать не нужно.

## Шаги

1. **Номер версии.** В `Cargo.toml` (раздел `[workspace.package]`) и
   в `app/package.json` — одинаковый, например `0.2.0`. Версия приложения
   берётся из `Cargo.toml`. Изменение — обычным PR в `main`.
2. **Метка.** После слияния PR — метка на `main`:
   ```sh
   git checkout main && git pull
   git tag v0.2.0
   git push origin v0.2.0
   ```
   Или попросить Claude. Если номер в метке не совпадает с `Cargo.toml`,
   сборка остановится с ошибкой.
3. **Сборка** — 20–30 минут, ход виден во вкладке Actions → «Выпуск».
   Появится черновик релиза с файлами:
   - `svg2tgs_X.Y.Z_windows_x64-setup.exe` — обычный установщик Windows;
   - `svg2tgs_X.Y.Z_windows_x64-offline-setup.exe` — с WebView2 внутри;
   - `svg2tgs_X.Y.Z_macos_universal.dmg` — macOS, Intel и Apple Silicon;
   - `svg2tgs_X.Y.Z_linux_amd64.deb` и `.AppImage`;
   - `svg2tgs-cli_X.Y.Z_*` — командная строка для каждой ОС;
   - `SHA256SUMS.txt` — контрольные суммы.
4. **Публикация.** Releases → черновик → «Edit»: описать изменения в разделе
   «Изменения» → «Publish release». До публикации черновик видят только
   участники репозитория.

Если сборка упала, исправьте ошибку обычным PR, удалите метку
(`git push origin :v0.2.0` и `git tag -d v0.2.0`) и поставьте её заново.

## Проверки

`.github/workflows/ci.yml` на каждый PR и на `main`: формат, clippy без
предупреждений, все тесты, сборка интерфейса — на Linux и Windows.
macOS проверяется только при выпуске: в приватном репозитории его минуты
расходуются в 10 раз быстрее (бесплатно — 2000 минут в месяц на всё).

## Подпись

Установщики пока без цифровой подписи: Windows показывает SmartScreen,
macOS — предупреждение Gatekeeper (как их пройти — в README). Подпись
добавляется без переделки сборки: сертификат Windows и аккаунт
разработчика Apple кладутся в секреты репозитория, а в `tauri.conf.json`
указываются их параметры.

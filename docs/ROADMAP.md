# План развития

Что уже умеет программа — [`SPEC.md`](SPEC.md). Здесь — что дальше и в каком
порядке. Оценки сложности — относительные: S — день-два, M — неделя,
L — больше недели.

## 0.1.x — довести первую версию

- Собрать установщик macOS (сейчас падает при выпуске).
- Проверить установку на чистых Windows 10/11, macOS и Linux.
- Перенести правки интерфейса из макета (`DESIGN.md`).
- Отложенное из первой версии (в SPEC отмечено **[позже]**): сортировка
  списка, режим «разница» в превью, настройки для отдельного файла,
  `.json` рядом с `.tgs` для отладки.
- Цифровая подпись установщиков — когда появятся сертификаты
  ([`RELEASE.md`](RELEASE.md), «Подпись»).

## 0.2 — нарезка в сетку эмодзи

Большая картинка режется на N×M клеток, каждая — отдельный эмодзи. В
сообщении клетки, поставленные подряд, складываются обратно в картинку
(«эмодзи-арт»).

- **Сложность: S–M.** Ядро уже умеет главное: геометрическую обрезку по
  прямоугольнику (так обрезается всё, что вылезает за канвас) и вписывание.
  Клетка — это тот же SVG с другим окном просмотра и обрезкой по нему;
  новой геометрии не нужно.
- **Что сделать:**
  - ядро: параметр «сетка» (столбцы × строки, или по ширине/высоте
    с сохранением пропорций), на выходе — список TGS по строкам;
  - имена `картинка_r1c1.tgs`, `картинка_r1c2.tgs`…, чтобы порядок
    загрузки в бота @Stickers был очевиден; рядом — текстовая подсказка
    с порядком;
  - интерфейс: сетка поверх превью, «как в чате» — вся мозаика в сообщении;
  - CLI: `--grid 4x3`.
- **Подводные камни:**
  - между эмодзи в сообщении есть зазоры, а в строке помещается
    ограниченное число эмодзи (зависит от экрана) — превью должно
    показывать это честно, а не идеальную картинку;
  - на краях клеток линии режутся, тонкие обводки на стыке могут
    «моргать» — нужен небольшой нахлёст или проверка попиксельным тестом;
  - лимит 64 КБ и точек считается на каждую клетку, обычно это проще,
    чем для целой картинки;
  - сколько эмодзи можно положить в один набор, в документации Telegram
    не указано — проверить у @Stickers до реализации.
- **Целесообразность: высокая.** Дёшево, востребовано для эмодзи-наборов,
  у похожих инструментов это делают вручную в редакторе.

## 0.3 — трассировка картинок (PNG, JPEG → вектор → TGS)

Растровая картинка переводится в контуры, дальше — обычный путь SVG → TGS.

- **Библиотека: [VTracer](https://github.com/visioncortex/vtracer)** —
  на Rust, лицензия MIT, цветная трассировка, пресеты «рисунок», «постер»,
  «фото», работает без сети. Potrace не подходит: GPL и только чёрно-белая.
- **Сложность: M.** Подключить библиотеку и чтение PNG/JPEG — несложно.
  Основная работа — подобрать настройки так, чтобы результат влезал в
  лимиты Telegram и выглядел прилично:
  - число цветов (4–16), сглаживание, отбрасывание мелких пятен;
  - связка с автоподгонкой размера: если не влезло — ещё меньше цветов
    и деталей, а не только упрощение контуров;
  - превью «оригинал / результат» и 2–3 пресета вместо десятка ручек.
- **Ограничение, о котором надо сказать пользователю честно:** хорошо
  получаются логотипы, иконки, рисунки, пиксель-арт, простые иллюстрации.
  Фотографии превращаются в «постер» из пятен: при лимите 64 КБ детали
  фото не сохранить. Это стоит прямо написать в интерфейсе.
- **Целесообразность: средняя.** Расширяет аудиторию (не у всех есть SVG),
  но качество сильно зависит от картинки. Хорошо сочетается с нарезкой:
  растровая картинка → трассировка → сетка эмодзи.

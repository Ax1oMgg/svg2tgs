## Выгрузка в Telegram через бота (0.2.0)

Готовые TGS сразу уходят в набор стикеров или эмодзи — без ручной загрузки
по одному файлу через @Stickers. Особенно нужно для нарезки: сетка 8 × 5 —
40 файлов в строгом порядке, каждому нужен эмодзи.

### Как устроено у Telegram

- Наборы создаёт **бот пользователя** через Bot API. Владелец набора —
  человек, менять набор может только создавший его бот. Дописывать можно
  только в наборы, созданные этим ботом.
- Общего бота у программы нет (токен оказался бы в открытом коде): каждый
  заводит своего у @BotFather, программа подсказывает шаги.
- Методы: `uploadStickerFile`, `createNewStickerSet`, `addStickerToSet`,
  `getStickerSet`, `setStickerPositionInSet`, `setStickerEmojiList`,
  `deleteStickerFromSet`.
- Пределы: набор эмодзи — до 200, набор стикеров — до 120.
  Имя `…_by_<бот>`, длина названия, число эмодзи на стикер — сверить
  с core.telegram.org перед кодом и закрепить тестами.

### Принцип «без сети»

- Выключено по умолчанию; пока переключатель в «Настройках» выключен,
  программа в сеть не обращается (отдельный тест).
- Запросы только к `api.telegram.org`, только по нажатию, из Rust с зашитым
  адресом. Интерфейс в сеть не ходит, CSP не меняется.
- Токен — в системном хранилище паролей (Windows, macOS, Secret Service),
  не в настройках и не в экспорте настроек.
- Поправить: `CLAUDE.md` («кроме выгрузки в Telegram по явному действию
  пользователя»), README («пока вы сами не выгрузите их в Telegram»),
  `SECURITY.md`.

### Для пользователя

1. «Настройки» → «Выгрузка в Telegram» → включить → токен → «Проверить»;
   программа показывает имя бота и просит написать ему /start, аккаунт
   владельца находит сама.
2. Кнопка «В Telegram» рядом с «Экспортировать» → окно: стикеры или эмодзи,
   название и адрес набора (окончание `_by_<бот>` — само), эмодзи — один
   на все файлы с правкой отдельных (для нарезки — по клеткам), порядок —
   как в списке.
3. Ход «23 из 40», «Остановить»; после обрыва — сверка с набором
   и продолжение.
4. Итог — ссылка `t.me/addstickers/…` или `t.me/addemoji/…`.
5. Ошибки — кодами ядра, текст — в интерфейсе и CLI.

### Код

- Крейт `publish`: клиент Bot API (rustls, повтор по `retry_after`),
  сценарий выгрузки, журнал продолжения.
- Tauri-команды; токен — крейт `keyring`.
- CLI `svg2tgs publish папка --set имя --title "…" --emoji ⭐`; токен —
  из переменной окружения.
- Тесты на заглушке Bot API; CI в Telegram не ходит.

## 0.3 — трассировка картинок (PNG, JPEG, WebP → вектор → TGS)

Растровая картинка переводится в контуры, дальше — обычный путь SVG → TGS:
трассировка выдаёт SVG, его разбирает usvg (`core::parse_svg`), затем
вписывание, обводка, нарезка, автоподгонка — как для любого SVG.

Честное ограничение: хорошо получаются логотипы, иконки, рисунки,
пиксель-арт, простые иллюстрации. Фотография при лимите 64 КБ становится
«постером» из пятен — интерфейс об этом говорит (см. ниже).

### Решено

- **Где:** приложение, CLI и веб-версия сразу, в одном выпуске 0.3.0.
- **Библиотека:** [visioncortex](https://github.com/visioncortex/visioncortex)
  0.9 (MIT OR Apache-2.0) и своя обёртка, перенесённая из
  [VTracer](https://github.com/visioncortex/vtracer) (MIT), — авторство
  в `THIRD_PARTY_NOTICES.md`. Сам крейт `vtracer` не берём: он тянет
  `image` 0.23, `clap` 2 и `visioncortex` 0.8. Potrace не подходит: GPL
  и только чёрно-белая. Случайность в кластеризации — с постоянным seed,
  чтобы результат повторялся (тесты, программа и веб совпадают).
- **Крейт:** новый `trace` (ядро остаётся без лишних зависимостей);
  подключают `cli`, `app/src-tauri`, `web`. Без сетевого кода, без импортов
  в WebAssembly.
- **Форматы:** PNG, JPEG, WebP; декодеры на чистом Rust (`png`,
  `zune-jpeg`, `image-webp`). Анимированные GIF и WebP не переводим.
- **Пресеты:** «Рисунок / логотип», «Пиксель-арт» (квадратные пиксели,
  без сглаживания контуров), «Фото → постер», плюс один ползунок
  «Детализация» (число цветов и порог мелких пятен вместе). «Пиксель-арт»
  подставляется сам для картинок до 128 px с малым числом цветов, его
  можно сменить. Настройки трассировки — у каждого файла, по умолчанию
  общие.
- **Прозрачность:** плавный спад непрозрачности (мягкие тени, края)
  становится градиентом прозрачности — конвертер уже выдаёт точки
  непрозрачности (`convert.rs`, `stops`); как их рисует rlottie, проверяет
  тест. Где градиент не подошёл — порог 50 %, заливка непрозрачная.
- **«Убрать фон»:** сплошной цвет по углам картинки (JPEG с белым фоном)
  становится прозрачным.
- **Рабочий масштаб:** считается от того, сколько пикселей рисунок займёт
  на холсте (после вписывания, отступа, обводки, масштаба, обрезки),
  а не от длинной стороны исходника:
  `масштаб = min(1, k × размер на холсте / размер исходника)`, где k —
  пикселей трассировки на пиксель канваса 512. Растр не увеличивается
  (кроме маленьких сглаженных логотипов, если замер покажет пользу).
  - k зависит от пресета и вида результата: «Рисунок» — около 1,
    «Фото» — около 0,5, клетка нарезки — меньше, чем стикер (эмодзи
    показываются мелко, а 64 КБ — у каждой клетки). «Пиксель-арт» —
    без передискретизации: родной размер или уменьшение в целое число раз
    по найденному шагу блоков.
  - Ограничение — по числу пикселей, а не по стороне (в вебе может быть
    ниже: один поток, память WebAssembly).
  - Пороги VTracer (пятна, длина отрезка, угол) задаются в пикселях
    канваса и пересчитываются в пиксели трассировки — «Детализация»
    значит одно и то же при любом масштабе.
  - Масштаб округляется ступенями (например, через √2), результат
    кэшируется: ползунки отступа и масштаба не запускают трассировку
    на каждый шаг.
  - В интерфейсе настройки нет; в CLI — `--trace-scale K` для отладки.
- **Автоподгонка:** если файл больше 64 КБ — сначала меньше k, затем
  ступенями меньше цветов и крупнее порог пятен, затем обычное упрощение
  контуров; градиенты не убираются. Замечание говорит, что урезано.
- **Фото:** определяется по числу уникальных цветов; предупреждение
  «Фото станет постером из пятен», не запрет.
- **Растр внутри SVG** (`<image>`, сейчас `ImageRemoved`) — не в 0.3.
- **CLI:** `--trace drawing|pixel|photo`, `--colors N`, `--remove-bg`,
  `--trace-scale K` (без флага — автоматически), `--no-gradients`;
  значения — по-английски, как у остальных флагов.
- **Макет:** все экраны, которые затрагивает трассировка (разрешено
  владельцем): растровый файл в списке, пресет, «Детализация», «Убрать
  фон», переключатель «Градиенты», превью «оригинал / результат»,
  замечания.
- **Проверка:** фикстуры и попиксельные тесты; большие наборы — без новых
  скачиваний: SVG из имеющихся наборов растеризуются resvg и трассируются
  обратно, считается, сколько влезло в лимит и расхождение с исходником.

### Градиенты

Трассировка делит картинку на области одного цвета: плавный переход
становится ступеньками, каждая — отдельный контур (и больше файл).
Конвертер уже выдаёт в TGS линейные и радиальные градиентные заливки
с точками непрозрачности (Telegram запрещает только градиентные обводки),
так что достаточно выдать SVG с `linearGradient`/`radialGradient`.
Своя доработка, в VTracer такого нет.

Решено:
- **В 0.3.0 — линейные** (цвет и прозрачность). Радиальные — в 0.3.x
  после отдельного замера (перебор центра около центра масс).
- **Приоритет — градиентам:** если условие ниже выполнено, фигура
  с градиентом берётся, даже когда полосы дали бы файл меньше;
  автоподгонка градиенты не убирает. Поэтому всё держится на точности
  условия — оно проверяется фикстурами в обе стороны (где градиент должен
  появиться и где нельзя).
- **Управление:** переключатель «Градиенты» у файла; по умолчанию включён
  в «Рисунке» и «Фото», выключен в «Пиксель-арте». CLI — `--no-gradients`.
  Замечание «N переходов заменены градиентом».
- **Перед разбиением** — лёгкое сглаживание шума (JPEG), только для поиска
  переходов; контуры строятся по исходнику.

Условие (триггер) — четыре проверки по порядку, все обязательны:
1. **Граница не настоящая.** Две соседние области — кандидаты, если граница
   между ними появилась от квантования, а не нарисована: перепад цвета
   поперёк границы в сглаженном исходнике не больше, чем в 2 раза выше
   перепада внутри областей на том же расстоянии. Это главный фильтр:
   резкая граница (флаг, контур логотипа) его не проходит, как бы близки
   ни были цвета.
2. **Соседство существенное.** Общая граница — не меньше 30 % периметра
   меньшей области (не касание углом); шаг цвета между соседями мал
   (ΔE в OKLab в пределах нескольких порогов заметности).
3. **Группа — один переход.** Кандидаты объединяются цепочкой; в группе
   не меньше 3 областей, площадь не меньше заданной в пикселях канваса;
   цвета (с прозрачностью) лежат около одной прямой (остаток после главной
   компоненты мал) и идут монотонно вдоль направления перехода. Текстура
   (большой разброс внутри областей) группу не даёт.
4. **Подгонка точна.** Направление и 2–3 точки подбираются наименьшими
   квадратами в sRGB — в нём интерполируют rlottie и lottie-web. Берётся,
   если ошибка по пикселям группы не больше, чем у полос, и 95-й процентиль
   ошибки ниже порога заметности (нет пятна, где градиент врёт). Третья
   точка — только если заметно снижает ошибку.

Открыто:
- Числа порогов (перепад на границе, 30 %, ΔE, площадь, процентиль) —
  по фикстурам и прогону наборов, итог — в `SPEC.md`.
- Как rlottie рисует градиенты с 3 точками и градиенты прозрачности
  на больших площадях. Если появятся свои полосы — обход в конвертере
  и тест, который без обхода падает.
- Если прогон покажет, что подход не оправдывается, — 0.3.0 выходит
  с полосами и честным замечанием, градиенты — позже.

### Не решено

- **Значения пресетов** (число цветов, порог пятен, сглаживание) —
  подбираются на этапе 2 по прогону наборов, итог — в `SPEC.md`.
- **Хранение настроек трассировки у файла** — сверить с тем, как сейчас
  хранятся настройки файла; варианты: отдельный блок в `Options`
  (попадает в экспорт настроек и `--options`) или только в программе.
  Предложение — в `Options`, чтобы CLI повторял программу.
- **Граница «пиксель-арта» и «фото»** (размер, число цветов) — по прогону.
- **k и ограничение пикселей** — по прогону: растеризация SVG наборов
  в 256/1024/4096 px, трассировка с k = 0,5/0,75/1/1,5/2; размер, доля
  в лимите, расхождение с исходником на 512, время. Берётся «колено» —
  отдельно для стикера, клетки эмодзи и каждого пресета.

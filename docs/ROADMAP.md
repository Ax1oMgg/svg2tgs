## Выгрузка в Telegram через бота (0.2.0)

Готовые TGS сразу уходят в набор стикеров или эмодзи — без ручной загрузки
по одному файлу через @Stickers. Особенно нужно для нарезки: сетка 8 × 5 —
40 файлов в строгом порядке, каждому нужен эмодзи.

### Как устроено у Telegram

- Наборы создаёт **бот пользователя** через Bot API. Владелец набора —
  человек, менять набор может только создавший его бот. Дописывать можно
  только в наборы, созданные этим ботом.
- Общего бота у программы нет (токен оказался бы в открытом коде): каждый
  заводит своего у @BotFather, программа подсказывает шаги.
- Методы: `uploadStickerFile`, `createNewStickerSet`, `addStickerToSet`,
  `getStickerSet`, `setStickerPositionInSet`, `setStickerEmojiList`,
  `deleteStickerFromSet`.
- Пределы: набор эмодзи — до 200, набор стикеров — до 120.
  Имя `…_by_<бот>`, длина названия, число эмодзи на стикер — сверить
  с core.telegram.org перед кодом и закрепить тестами.

### Принцип «без сети»

- Выключено по умолчанию; пока переключатель в «Настройках» выключен,
  программа в сеть не обращается (отдельный тест).
- Запросы только к `api.telegram.org`, только по нажатию, из Rust с зашитым
  адресом. Интерфейс в сеть не ходит, CSP не меняется.
- Токен — в системном хранилище паролей (Windows, macOS, Secret Service),
  не в настройках и не в экспорте настроек.
- Поправить: `CLAUDE.md` («кроме выгрузки в Telegram по явному действию
  пользователя»), README («пока вы сами не выгрузите их в Telegram»),
  `SECURITY.md`.

### Для пользователя

1. «Настройки» → «Выгрузка в Telegram» → включить → токен → «Проверить»;
   программа показывает имя бота и просит написать ему /start, аккаунт
   владельца находит сама.
2. Кнопка «В Telegram» рядом с «Экспортировать» → окно: стикеры или эмодзи,
   название и адрес набора (окончание `_by_<бот>` — само), эмодзи — один
   на все файлы с правкой отдельных (для нарезки — по клеткам), порядок —
   как в списке.
3. Ход «23 из 40», «Остановить»; после обрыва — сверка с набором
   и продолжение.
4. Итог — ссылка `t.me/addstickers/…` или `t.me/addemoji/…`.
5. Ошибки — кодами ядра, текст — в интерфейсе и CLI.

### Код

- Крейт `publish`: клиент Bot API (rustls, повтор по `retry_after`),
  сценарий выгрузки, журнал продолжения.
- Tauri-команды; токен — крейт `keyring`.
- CLI `svg2tgs publish папка --set имя --title "…" --emoji ⭐`; токен —
  из переменной окружения.
- Тесты на заглушке Bot API; CI в Telegram не ходит.

## Веб-версия — svg2tgs в браузере (после перевода репозитория в публичный)

Сайт `ax1omgg.github.io/svg2tgs` на GitHub Pages: открыл — и работаешь,
ничего не устанавливая. Вся обработка — на компьютере пользователя
(WebAssembly, фоновый поток), файлы никуда не загружаются.

- **Шаги** (каждый можно выпустить отдельно):
  1. ядро в WebAssembly, `backend.ts` для браузера, загрузка файлов,
     скачивание `.tgs` (несколько файлов и нарезка — одним `.zip`);
  2. превью исходника — resvg в WebAssembly;
  3. rlottie в WebAssembly (Emscripten, как в Telegram Web) — превью
     «как в Telegram»; до этого шага превью результата строится по исходнику
     и подписано «приблизительно»;
  4. выкладка на Pages из Actions при каждом выпуске, раздел в README.
- **Что в браузере не работает или работает иначе:**

  | Функция | В браузере |
  |---|---|
  | Сохранить рядом с исходником, подпапка | нет: скачивание `.tgs` / `.zip` |
  | Выбор папки экспорта | только Chrome и Edge |
  | Добавить папку целиком | только Chrome и Edge |
  | Публикация в Telegram | нет: Telegram не принимает запросы со сторонних сайтов |
  | Текст в SVG | 1–2 встроенных шрифта, редкие подменяются (с замечанием) |
  | Настройки, тема, язык | как в программе, хранятся в браузере |

- **В интерфейсе всё недоступное видно:** выключенные кнопки и поля
  с подсказкой при наведении («Доступно в установленной версии» и причина).
  При первом запуске — одна плашка о веб-версии и её ограничениях
  (закрывается и больше не показывается). Ссылки на веб-версию из
  программы нет.
- **Подводные камни:** первая загрузка 3–5 МБ (дальше — из кэша); большие
  наборы обрабатываются медленнее; одно ядро и одни тесты для обеих сборок,
  чтобы они не расходились.
- **Сложность: M–L. Целесообразность: высокая** — самый короткий путь для
  новых людей: прислал ссылку — человек сразу пробует.

## 0.3 — трассировка картинок (PNG, JPEG → вектор → TGS)

Растровая картинка переводится в контуры, дальше — обычный путь SVG → TGS.

- **Библиотека: [VTracer](https://github.com/visioncortex/vtracer)** —
  на Rust, лицензия MIT, цветная трассировка, пресеты «рисунок», «постер»,
  «фото», работает без сети. Potrace не подходит: GPL и только чёрно-белая.
- **Сложность: M.** Подключить библиотеку и чтение PNG/JPEG — несложно.
  Основная работа — подобрать настройки так, чтобы результат влезал в
  лимиты Telegram и выглядел прилично:
  - число цветов (4–16), сглаживание, отбрасывание мелких пятен;
  - связка с автоподгонкой размера: если не влезло — ещё меньше цветов
    и деталей, а не только упрощение контуров;
  - превью «оригинал / результат» и 2–3 пресета вместо десятка ручек.
- **Ограничение, о котором надо сказать пользователю честно:** хорошо
  получаются логотипы, иконки, рисунки, пиксель-арт, простые иллюстрации.
  Фотографии превращаются в «постер» из пятен: при лимите 64 КБ детали
  фото не сохранить. Это стоит прямо написать в интерфейсе.
- **Целесообразность: средняя.** Расширяет аудиторию (не у всех есть SVG),
  но качество сильно зависит от картинки. Хорошо сочетается с нарезкой
  (0.1.5): растровая картинка → трассировка → сетка эмодзи.

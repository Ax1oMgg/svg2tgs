# svg2tgs — описание функционала

Настольное приложение для Windows, macOS и Linux, которое превращает SVG
в стикеры и эмодзи Telegram (формат TGS). Работает полностью локально:
не обращается к сети, не собирает телеметрию, не проверяет обновления.
Исключение — выгрузка готовых стикеров в Telegram (раздел 8): только
к `api.telegram.org` и только по команде пользователя.

Отметки: **[MVP]** — первая версия, **[позже]** — после неё.

## Сценарий

Открыл программу → перетащил SVG → увидел превью и замечания → нажал
«Экспортировать». Настройки по умолчанию подобраны под Telegram, большинству
пользователей не нужно ничего трогать, кроме выбора пресета.

## 1. Добавление файлов
- **[MVP]** Перетаскивание файлов и папок в окно.
- **[MVP]** Над списком — кнопка «Добавить» (файлы) и прижатая к ней
  кнопка-папка (папка целиком); на пустом экране — «Добавить файлы»,
  «Добавить папку» и галочка «включая вложенные».
- **[MVP]** Вставка SVG-кода из буфера (Ctrl+V / ⌘V), например после
  «Copy as SVG» в Figma.
- **[MVP]** Повторно добавленный файл не дублируется.

## 2. Список файлов
- **[MVP]** Миниатюра, имя, размер итогового `.tgs`, статус:
  ✓ готово · ⚠ есть замечания · ✗ ошибка.
- **[MVP]** Длинное имя обрезается посередине: последние 16 символов
  видны всегда (если в пределах 4 символов левее есть пробел, `_` или `-`,
  хвост начинается с него); полное имя — во всплывающей подсказке и над превью.
- **[MVP]** Миниатюра — результат; у нарезки — вся мозаика, вписанная
  в квадрат с полями (без растяжения).
- **[MVP]** Выбор нескольких файлов: Ctrl — добавить или убрать, Shift —
  подряд. Все выбранные подсвечены одинаково; какой показан в превью — видно
  по имени над превью. Рамка фокуса строки — только при работе с клавиатуры.
- **[MVP]** Внизу списка — сводка, а во время конвертации — полоска
  прогресса, процент и три числа: без замечаний, с замечаниями, с ошибкой.
- **[MVP]** Конвертация сразу при добавлении, в фоне и параллельно;
  интерфейс не подвисает.
- **[MVP]** Удаление из списка, «Очистить всё», фильтр «только проблемные».
- **[позже]** Сортировка по имени, размеру, статусу.

## 3. Превью
- **[MVP]** Две панели: исходный SVG и результат TGS, отрисованный тем же
  движком, что у Telegram (rlottie).
- **[MVP]** Фон: светлый чат, тёмный чат, шахматка.
- **[MVP]** Масштаб: «как в чате» (реальный размер стикера или эмодзи
  в строке текста) и крупно.
- **[MVP]** Вид «Стикер / Эмодзи» — переключатель в панели превью между
  «Как в чате / Крупно» и выбором фона. Меняет только показ: эмодзи —
  в строке текста, крупным сообщением и реакцией собеседника; в виде
  «Эмодзи» видна проверка тонких линий. Файл не пересобирается, выбор
  запоминается.
- **[MVP]** «Крупно»: масштаб 100–800 % и сдвиг — общие для обеих
  половин (действие в одной повторяется в другой). Колёсико — масштаб
  вокруг курсора, перетаскивание — сдвиг, двойной щелчок или «По размеру» —
  100 %. При увеличении превью перерисовывается крупнее (до 2048 px).
- **[MVP]** Широкий чат: если область чата шире 720 px (порог на глаз),
  свои сообщения встают слева, как в Telegram Desktop.
- **[MVP]** Подпись исходника в «Крупно»: «Исходный SVG», если настройки
  рисунок не меняют, иначе «Модифицированный SVG»; результат — «Так покажет
  Telegram».
- **[позже]** Режим «разница»: подсветка мест, где результат отличается.

## 4. Замечания и ошибки
- **[MVP]** Для каждого файла понятный список изменений с причиной, например:
  «Размытие не поддерживается в Telegram и было убрано», «Текст переведён
  в кривые», «Файл 71 КБ при лимите 64 КБ — включите автоподгонку».
- **[MVP]** Ошибки без технических подробностей: «Файл повреждён или это не SVG».
- **[MVP]** Текст переводится в кривые установленными шрифтами. Если
  указанного шрифта нет, берётся похожий установленный (без засечек,
  с засечками, моноширинный); если шрифтов нет совсем, текст убирается
  с замечанием «текст не удалось перевести в кривые».
- Ядро возвращает замечания как коды с параметрами (`core/src/report.rs`),
  интерфейс и CLI переводят их на язык пользователя.

## 5. Настройки конвертации
Правая колонка — «Панель экспорта» (ширина 310 px). Переключатель
«Настройки экспорта: Всех файлов / Этого файла» выбирает, что правится:
общие настройки или свои настройки выбранного файла. Если в списке выбрано
несколько файлов (Ctrl — добавить к выбору, Shift — подряд), второй вариант
называется «Выбранных файлов»: изменённая настройка записывается в свои
настройки каждого выбранного файла, остальные их настройки не трогаются.
Файл со своими настройками помечен в списке («свои настройки»); при смене
общих он не пересчитывается. Возврат на «Всех файлов» снимает свои
настройки. В своих настройках сброс раздела означает «как в общих».

Если файлов несколько, все на общих настройках, и меняется что-то из
«Трансформации» или положение X/Y, правка уходит только в выбранные файлы:
у них появляются свои настройки, а внизу — уведомление с таймером (6 с,
пауза при наведении) и кнопкой «Отменить».

Ctrl+Z отменяет правку настроек, Ctrl+Shift+Z (или Ctrl+Y) возвращает;
частые правки подряд (перетаскивание ползунка) — один шаг. В текстовых
полях (суффикс, префикс, подпапка) действует их собственная отмена.

Шапка панели («Панель экспорта», «Экспортировать N», значок «только этот
файл») не прокручивается, как у «Файлов». Порядок ниже: папка,
суффикс/префикс/подпапка (при каждом запуске выключены, текст помнится;
после установки пустые), «Настройки экспорта», «Результат» (один файл
или нарезка на эмодзи), затем разделы «Положение», «Трансформация»,
«Оформление», «Фон», «Дополнительно» («Размер файла», импорт и экспорт
настроек). При запуске все разделы свёрнуты. Раскрытость своя у каждого
набора настроек: общая у «Всех файлов» и своя у каждого файла со своими
настройками (начинается с раскрытости общих); помнится до закрытия
программы. При смене файла или области панель не прокручивается к началу.
Названия разделов — полужирные, названия настроек — средней насыщенности,
подсказки — обычным шрифтом. У каждого раздела и у
«Настройки экспорта» справа кнопка сброса (неактивна, если менять нечего).
Выбор из 2–4 вариантов — сегментный переключатель.

Клавиши одинаковы для ползунков (перетаскивание), стрелок в числовом поле
и колёсика над полем в фокусе:
- Alt (⌥) или Ctrl — плавно, шаг в 10 раз мельче;
- Shift — шагами поля: поворот 15°, X/Y 5 %, отступ 4 px, масштаб
  и пропорции 10 %, скругление 8 px, толщина 4 px;
- Shift+Alt — плавно, но с шагом 1.

fps и длительность в интерфейсе не настраиваются (Telegram требует 60 кадров/с,
рисунок статичный) — только в командной строке.

Канвас, fps, длительность и лимит размера — по требованиям Telegram
(https://core.telegram.org/stickers, сверено 24.10.2026): канвас 512×512,
60 кадров/с, не дольше 3 с, файл до 64 КБ — одинаково для стикеров
и анимированных эмодзи, поэтому «Стикер / Эмодзи» — только вид превью
(раздел 3), а не настройка экспорта. Если флаги командной строки нарушают
требования, файл всё равно создаётся, но с замечанием.

### Соответствие правилам Telegram
- Telegram запрещает в TGS маски, градиентные обводки, merge paths, repeater,
  текстовые и картиночные слои, сплошные слои, 3D, эффекты. Конвертер их
  не выдаёт: `clipPath` применяется геометрически, градиентная обводка
  становится залитым контуром.
- Объекты не выходят за канвас: всё лишнее обрезается геометрически.

### Трансформация и положение
Рисунок проходит цепочку, каждый шаг работает с результатом предыдущего:
рамка рисунка (по контейнеру или по краю) →
отразить → пропорции → повернуть → обрезать по рамке обрезки → вписать
в рабочую область (холст минус отступ и место под обводку) → положение X/Y
(доля свободного места; если рисунок больше области — какая часть видна) →
обводка вокруг того, что осталось → фон (скругление, обрезка по фону,
заливка, обводка фона). Всё, что вышло за рабочую область или рамку
обрезки, отрезается, поэтому отступ — всегда чистое поле со всех сторон.
Превью исходника режет так же.

Рамка обрезки задаётся от рамки рисунка **без поворота** и стоит
относительно его центра: при повороте она не двигается, поворачивается
рисунок под ней (у повёрнутого рисунка рамка может быть шире исходной —
отступы отрицательные). Без обрезки рамка — весь повёрнутый рисунок.

«По краю» рамка рисунка считается по самому рисунку уже после отражения,
пропорций и поворота (точные границы контуров с толщиной обводок): круг
при любом угле занимает то же место, квадрат при 45° вписывается по
диагонали. «По контейнеру» поворачивается вся область документа.

### Кадрирование мышью
«Кадрировать» открывает в превью рамку обрезки поверх рисунка: края и
углы — обрезать, перетаскивание внутри — сдвинуть рамку, кружок над
рамкой — повернуть (Shift — шаг 15°, Alt или Ctrl — точнее). «Сбросить» убирает
обрезку и поворот, «Готово» закрывает кадрирование.

### Фон
- Заливка и обводка фона — квадрат на весь канвас со скруглёнными углами.
- Обводка фона лежит внутри канваса: внешний край совпадает с краем фона,
  внутренний скруглён радиусом «скругление − толщина». Порядок слоёв
  сверху вниз: рисунок, обводка рисунка, обводка фона, заливка фона.
- «Обрезка по фону» (по умолчанию включена): рисунок и его обводка
  обрезаются по скруглённой рамке фона — по внутреннему краю обводки фона,
  если она есть. Действует, только когда фон виден (есть заливка или
  обводка фона).

### Нарезка на эмодзи
- «Результат: Нарезка на эмодзи» раскладывает рисунок на сетку
  «столбцы × строки»; каждая клетка — отдельный TGS 512×512. Все шаги
  (вписывание, отступ, обводка, фон) считаются для всего холста сетки,
  поэтому клетки, поставленные вплотную, дают цельную картинку: обводка
  идёт вокруг рисунка, а не вдоль разрезов, фон со скруглением — на весь
  холст.
- Ползунок «Крупнее … Детальнее» задаёт число столбцов (1–20), строки
  подстраиваются по пропорциям рисунка — клетки остаются квадратными.
- Сетка по умолчанию подбирается по пропорциям рисунка после трансформаций
  и обрезки: не больше 8 столбцов, из вариантов с самым близким
  соотношением сторон — самый крупный (1,6 : 1 → 8 × 5, 3 : 2 → 6 × 4).
  8 в ряд — столько эмодзи клиенты Telegram показывают в ряд (панель
  эмодзи); это практика клиентов, в документации Telegram числа нет.
  Числа можно поменять вручную (1–20), палочка возвращает подбор. Больше
  8 столбцов — предупреждение: в Telegram ряды разъедутся.
- Файлы: `имя_01.tgs … имя_N.tgs` по строкам слева направо — в этом порядке
  их загружать в набор. Пустые клетки тоже сохраняются (прозрачные), чтобы
  сетка не съехала. Если какой-то из этих файлов уже есть, окно совпадения
  спрашивает про всю сетку сразу.
- Превью «Как в чате» — сообщение из эмодзи вплотную; «Крупно» — исходник
  с сеткой и номерами клеток (номер = номер файла) и сборка из клеток.

### Обводка вокруг рисунка
- Как у вырезанных стикеров: силуэт всех видимых заливок и обводок
  расширяется на заданную толщину со скруглёнными углами; дырки внутри
  силуэта заливаются. Слой обводки лежит под рисунком и над фоном.
- Место под обводку вычитается при вписывании: рисунок с обводкой
  помещается в канвас с тем же отступом от края.

### Оптимизация размера
- **Авто** (по умолчанию): контуры упрощаются с отклонением до 0,05 px —
  невидимо. Если файл больше 64 КБ, отклонение и точность чисел
  повышаются ступенями (0,1 → 0,25 → 0,5 → 1 → 1,5 → 2,5 px), пока файл
  не влезет. Пользователь видит замечание с итоговым отклонением; до 0,5 px
  оно справочное, от 0,5 px — предупреждение.
- **Без потерь**: без упрощения, 3 знака после запятой.
- **Ручная точность**: заданное число знаков, упрощение 0,05 px.

### Проверки для эмодзи
- Линии тоньше 12 px на канвасе 512 (≈ полпикселя в строке текста)
  дают предупреждение: в сообщении они почти пропадут. Это оценка
  svg2tgs, а не требование Telegram. В приложении замечание видно в виде
  «Эмодзи» и не влияет на значок файла в списке.

## 6. Экспорт
- **[MVP]** Кнопка «Экспортировать N» вверху панели экспорта сохраняет все
  файлы списка (N — сколько их), без промежуточного окна. Если что-то ещё
  конвертируется, экспорт дожидается конца; файлы с ошибкой не сохраняются,
  и сводка говорит, сколько их.
- **[MVP]** Значок рядом (файл со стрелкой вниз) сохраняет только выбранный
  файл: один TGS или, при нарезке, все эмодзи его сетки; подсказка
  называет, что именно.
- **[MVP]** Папка: по умолчанию «В папку источника» — каждый TGS рядом
  со своим SVG; «Выбрать» задаёт общую папку, «×» возвращает «В папку
  источника». Для SVG из буфера, если общая папка не задана, программа
  спрашивает папку при экспорте.
- **[MVP]** Имя: префикс + имя SVG + суффикс; подпапка внутри папки
  экспорта. Каждое поле включается флажком; по умолчанию все три
  выключены и пустые.
- **[MVP]** Если файл уже есть — окно «<имя> уже существует» по каждому
  совпадению: «Сохранить» под новым именем (поле, по умолчанию `heart_tg_1`;
  `.tgs` не редактируется), «Перезаписать», «Пропустить», «Отмена» (экспорт
  отменяется, ничего не записывается). «Применить ко всем · ещё N» — тот же
  выбор для остальных, новые имена — с номером по порядку.
- **[MVP]** Импорт и экспорт настроек («Дополнительно»): «Вставить»
  (окно с полем, текст разбирается при вводе, ошибка — со строкой
  и столбцом), «Из файла…», «Скопировать», «В файл…». Формат — JSON
  настроек ядра с меткой `"format": "svg2tgs-options/1"`, тот же, что
  у `svg2tgs --options`. Действует на то, что сейчас правится («Всех
  файлов» или свои настройки выбранных); папка и имена файлов не входят.
  Неизвестные поля пропускаются, недостающие — по умолчанию; вставку
  можно отменить Ctrl+Z. Файл выбирается диалогом в Rust — окно программы
  не передаёт путей и не читает файлы само.
- **[MVP]** После экспорта — сводка и «Открыть папку», если все файлы
  легли в одну папку. Сводка закрывается при первом новом действии
  (щелчок или клавиша вне неё); уведомление с «Отменить» — по таймеру.
- **[позже]** Дополнительно `.json` (Lottie без сжатия) для отладки.

## 7. Настройки программы
- **[MVP]** Окно «Настройки» — по кнопке-шестерёнке в верхней панели.
  Название программы — в заголовке окна ОС: «svg2tgs by Чайная Аксиома».
- **[MVP]** Язык (выпадающий список) — из файлов переводов
  `app/src/locales/<код>.json` (сейчас русский и английский); при первом
  запуске — язык системы, если для него есть перевод, иначе английский.
  Перевод — только данные (строки с подстановками `{имя}`), его проверяет
  сборка; как добавить язык — `docs/TRANSLATIONS.md`. Тема
  (переключатель): как в системе, светлая, тёмная.
- **[MVP]** Выбор применяется кнопкой «Готово» (активна, когда что-то
  изменено); «×», Esc или щелчок мимо окна закрывают его без изменений.
- **[MVP]** «О программе»: иконка программы (52 px) слева от названия
  с версией и Telegram-канала «Чайная Аксиома» (название канала —
  по-русски на любом языке); ниже автор
  (Парамонов Григорий aka Ax1oMgg), лицензия MIT, страница проекта и
  «Сообщить о проблеме» (GitHub Issues), почта. Ссылки — текстом,
  открываются вне программы; адреса зашиты в Rust (белый список).
- **[MVP]** Запоминание последних настроек и параметров экспорта.
- «Выгрузка в Telegram» — между «Темой» и «О программе», действует сразу
  (кнопка «Готово» к ней не относится):
  - переключатель, по умолчанию выключен; пока выключен, программа в сеть
    не обращается — это проверяет Rust, а не окно;
  - включили → поле «Токен бота» (скрыт, как пароль) и «Проверить»;
    подсказка со ссылкой на @BotFather; неверный токен — ошибка под полем;
  - токен принят → «Бот @имя найден», просьба написать ему /start; пока окно
    открыто, программа раз в 3 с спрашивает Telegram, написали ли;
    «Открыть бота», «Другой токен»;
  - владелец найден → «@бот, наборы создаются в аккаунт @ник» (нет ника —
    имя из профиля), «Отключить» забывает токен и аккаунт;
  - токен — в системном хранилище паролей (Диспетчер учётных данных
    Windows, Связка ключей macOS, Secret Service в Linux); переключатель,
    имя бота и владелец — в `telegram.json` в папке настроек, без токена.
- Кнопка «В Telegram» (значок «самолётик») — в шапке панели экспорта,
  рядом с экспортом, видна только при включённой выгрузке; без
  подключённого бота неактивна с подсказкой. Выгружает клетки нарезки
  выбранного файла (тип по умолчанию — эмодзи), иначе — все готовые файлы
  списка по порядку (тип — по виду превью). Окно выгрузки:
  - тип (стикеры / эмодзи), набор: «Новый» («Дописать» — позже,
    неактивно), название, адрес (из названия, `_by_<бот>` — само);
  - эмодзи «для всех» и свои: у файлов — в списке, у клеток — щелчок по
    клетке картинки; можно несколько эмодзи подряд;
  - ход «N из M» с «Остановить» (окно во время выгрузки не закрывается);
    обрыв связи или остановка — «Продолжить» дописывает недостающее;
  - итог — ссылка на набор, «Скопировать», «Открыть в Telegram».

## 8. Командная строка
- **[MVP]** `svg2tgs` — тот же движок для пакетной обработки и скриптов.
  Флаги: `-o` папка, `--preset sticker|emoji`, `-r` вложенные папки,
  `--on-conflict number|overwrite|skip`, `--padding` (%),
  `--bounds container|content`, `--fit contain|cover|width|height|free`, `--scale` (%), `--position X,Y` (%),
  `--flip-h`, `--flip-v`, `--rotate` (°), `--aspect` (%), `--crop В,П,Н,Л`
  (% рамки рисунка без поворота), `--bg #rrggbb`, `--bg-radius 64`,
  `--bg-border 12[:#rrggbb]`, `--no-bg-clip`, `--outline 12[:#rrggbb]`,
  `--grid 8x5|auto` (нарезка на эмодзи: `имя_01.tgs`…),
  `--options файл.json` (настройки из программы; флаги — поверх файла),
  `--optimize auto|lossless|0–6`,
  `--fps`, `--duration`, `--json` (отчёт для скриптов), `-j` (потоки).
  В конце — сводка: сколько с замечаниями, пропущено, больше лимита.
- Одинаковые имена из разных папок не затирают друг друга: второй файл
  получает номер `icon_1.tgs`.
- Файлы обрабатываются параллельно, вывод — в порядке входных файлов.
- Коды выхода: 0 — всё сконвертировано, 1 — нечего обрабатывать,
  2 — часть файлов с ошибкой.
- В консоли Windows включается UTF-8, чтобы кириллица и значки
  отображались и в старом cmd.exe.
- `svg2tgs publish файлы_или_папки --title "…"` — выгрузка готовых `.tgs`
  в новый набор Telegram через бота пользователя (Bot API):
  - токен бота — из переменной окружения `SVG2TGS_BOT_TOKEN`, не из
    аргументов (их видно в списке процессов); бота создают у @BotFather;
  - владелец наборов — тот, кто последним написал боту `/start` в личку,
    или `--user-id`;
  - `--kind sticker|emoji`, `--emoji ❤️[,😍…]` — эмодзи для всех файлов
    (1–20, по умолчанию ⭐), `--name` — адрес без `_by_<бот>` (по
    умолчанию — из названия, кириллица транслитом);
  - файлы из папки — по порядку имён; адрес набора проверяется по
    правилам Telegram до запросов (латиница, цифры, одиночные `_`,
    с буквы, до 64 символов), название — 1–64 символа, в наборе стикеров
    до 120, эмодзи — до 200;
  - ход «N из M»; если Telegram просит подождать (429) — ждёт и повторяет;
  - при обрыве уже выгруженное остаётся в наборе, `--resume` дописывает
    недостающее (сверяясь с числом стикеров в наборе); без `--resume`
    существующий набор не трогается — «имя занято»;
  - итог — ссылка `t.me/addstickers/…` или `t.me/addemoji/…`; `--json` —
    итог или код ошибки одной строкой;
  - коды выхода: 0 — набор готов, 1 — неверные параметры или нет токена,
    2 — ошибка выгрузки.

## 9. Поставка
- Windows: два установщика, ставятся без прав администратора —
  - **обычный**: если в системе нет WebView2, установщик скачает его;
  - **офлайн**: WebView2 вшит в установщик (≈ +130 МБ), установка без интернета.
- macOS 10.15+: `.dmg`, один файл для Intel и Apple Silicon.
- Linux: `.deb` и `.AppImage`.
- Командная строка — отдельные архивы для каждой ОС.
- Установщики собирает GitHub Actions по метке версии, к релизу
  прикладываются контрольные суммы SHA-256 (`docs/RELEASE.md`).
- Пока без цифровой подписи: при первом запуске Windows и macOS
  предупреждают о неизвестном издателе (как пройти — в README).
- Внутри установки — `LICENSE.txt` и `THIRD_PARTY_NOTICES.md`.
